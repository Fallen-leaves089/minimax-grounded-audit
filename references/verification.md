# 验证与完成判定

## 1. 证据账本

开始执行命令前先建立账本，至少记录：

```text
检查项 | 命令/工具 | cwd | 退出码 | 关键输出 | 产物 | 状态 | 未覆盖原因
```

状态只用：`verified`、`observed`、`inferred`、`not-covered`。`verified` 必须有可复跑证据；`observed` 只说明本次看到；`inferred` 必须标明推断；`not-covered` 不能写成通过。

## 2. MiniMax Code 的 `Bash` 契约

- 带原生 `task_output` 时，前台命令最多等待约 60 秒，然后把同一进程转入后台；总超时默认 600 秒且上限 600 秒。
- 没有原生 `task_output` 时，前台默认约 120 秒、上限 300 秒。
- 显式 `run_in_background` 的命令按请求超时执行；省略时受约 30 分钟运行时看门狗约束。
- 大输出首响应只保留约 24 KiB 的头部和尾部；完整结果通过日志引用或 `task_output` 读取。
- `task_output` 使用字节偏移读取；成功的读取仍可能对应失败的命令，必须同时看退出码、信号和超时。
- 前台超时后命令可能继续在后台运行；启动不等于完成。

## 3. 完成判定

一个检查项只有在以下条件同时满足时才算完成：

- 命令或工具确实执行；
- 退出码为 0，或失败被明确记录；
- 关键输出已读取，没有只依赖截断预览；
- 后台任务已到终态；
- 业务产物存在且可复核；
- cwd、环境变量和前置条件与结论匹配。

后台任务必须读到终态和完整日志。只有退出码 0 才是成功。`/clear`、切换会话、按 Esc 和关闭面板对后台工作的影响不同，不能假定离开界面等于停止任务。

## 4. 假绿清单

以下都不能单独证明成功：

- 日志里出现 `PASS`、`OK`、`success` 或“通过”；
- 测试数量大于 0；
- 配置文件存在；
- 命令已启动或进入后台；
- 产物文件存在但未校验内容；
- 模型自己说“已检查”；
- 子代理返回“无问题”；
- CI 缓存命中；
- 旧报告或旧构建结果。

## 5. 上下文压缩

MiniMax Code 在约 70%-95% 上下文窗口时自动压缩，工具结果还可能有单独压缩。压缩后必须：

- 重读关键源文件和配置；
- 重查后台任务、权限模式和目标路径；
- 核对证据账本；
- 不直接把压缩前的“已通过”复制到压缩后。

## 6. PTC

使用 `run_code` 时：

- 记录 PTC 是否启用；
- 保留原始子调用和结果，或明确标记“摘要证据”；
- 关键结论回到直接工具调用；
- 子调用失败、参数缺失或结果为空时失败关闭。

## 7. 权限拒绝与安全拒绝

权限拒绝、安全拒绝、超时、输出不可读、工具缺失和后台任务未结束都属于未覆盖或未完成。不能改写成“没有发现问题”，也不能用推断补足。
