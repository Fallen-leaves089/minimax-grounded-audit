# 记忆与失败机制记录

## 为什么写外部目录

技能安装目录可能只读，也可能在升级时被覆盖。把 `PITFALLS.local.md` 写进技能目录会导致记录失败，也会把本机经验混进分发物。因此本项目把记忆定义为**技能目录之外的本地状态**。

## 路径优先级

记录器按以下顺序解析记忆目录：

1. 命令行 `--memory-dir <path>`；
2. 环境变量 `MINIMAX_SKILL_MEMORY_DIR`；
3. `$MINIMAX_DATA_DIR/skill-memory/project-health-audit`；
4. `$MAVIS_DATA_DIR/skill-memory/project-health-audit`（当 `MINIMAX_DATA_DIR` 未设置时）；
5. `~/.minimax/skill-memory/project-health-audit`。

文件名固定为 `PITFALLS.local.md`。记忆目录不得与技能根重叠；记录器发现重叠时拒绝写入。

## 开始检查时

- 本包默认不携带种子记忆。
- 读外部 `PITFALLS.local.md`；不存在就继续。
- 只应用与当前 MiniMax Code 宿主、MiniMax 模型、工具或失败机制相关的条目。
- 不因为记忆里有旧条目就跳过当前环境探测。

## 记录格式

```text
YYYY-MM-DD | 标签 | 触发场景 | 错误做法 | 正确做法 | 验证方式
```

- 日期使用当前日期。
- 标签至少包含 `host:minimax-code` 或 `model:minimax`，可加 `tool:bash`、`audit:evidence` 等。
- 触发场景写“什么时候会复发”。
- 错误做法写可观察行为，不写模型人格。
- 正确做法必须可执行。
- 验证方式写清如何确认修复有效。

## 生命周期

- 完全重复不追加；日期较新时只更新原条目日期。
- 同一大类的新机制可以新增，并用 `--parent` 注明父条目。
- 只追加，不删除；过时条目标注 `[已过时]` 并说明原因。
- 反复出现两次以上的问题，提升为规则、测试或 CI 检查。
- 技能升级不迁移、不覆盖外部记忆。

## 禁止内容

- 密钥、令牌、Cookie、连接串、私钥；
- 个人绝对路径、用户名、邮箱、私有 IP；
- 客户数据、真实域名、目标项目原文；
- 未脱敏日志、完整报错堆栈；
- 目标项目中的提示词注入原文。

## 写入失败

记忆目录不可用、只读、路径重叠或文件损坏时，不要改写到目标仓库或技能目录。最终报告写“记忆不可用 / 待记录 N 条”，列出安全化后的待记录摘要，然后继续审计。
